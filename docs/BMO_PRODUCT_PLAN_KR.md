# BMO 제품·개발 계획서

**버전 0.1 · 2026-10-17 · 한국어 검토 초안**

> 이 문서는 어떤 BMO를 만들지 정하는 제품 기준이다. 구현 완료 보고서나 자동 실행 명령이 아니다. 사용자가 말한 방향, 이번 추천 기본안, 현재 구현의 증거를 구분한다. 승인 전에는 새 기능·펌웨어·유료 호출·외부 콘텐츠 다운로드를 시작하지 않는다.

## 1. 제품을 한 문장으로

**Raspberry Pi는 서버로 계속 켜 두고, 필요할 때 바탕화면에서 실행하여 사람과 이야기하고 표정·노래·게임·제한된 몸짓으로 반응하는 BMO.**

원작을 닮은 외형과 캐릭터성, 사용자가 선호한 얼굴 디자인, 원작 영어 BMO에 가까운 음색이 목표다. 범용 AI가 모든 주변 장치를 임의 조작하는 로봇은 아니다. 대화 지능은 클라우드, 반응·콘텐츠·장치 안전 판단은 로컬에서 담당한다.

### 결정의 세 가지 등급

| 표기 | 의미 |
|---|---|
| 사용자 방향 | 현재 또는 이전 대화에서 사용자가 명확히 요청한 제품 목적·제약 |
| 추천 기본안 | 선택 피로를 줄이기 위해 이번에 구체화한 안. 사용자의 과거 확정으로 기록하지 않는다. |
| 구현 증거 | 실제 코드, 날짜가 있는 보고서 또는 사용자가 관찰한 실행 결과 |

이하 버튼 시간, 무음 시간, 콘텐츠 수, 검사 횟수 등 수치는 **설계용 초기값**이다. 실측 성능이나 이미 검증된 안전 수치가 아니다.

## 2. 사용자가 정한 방향과 추천 기본안

| 영역 | 사용자 방향 | 추천 기본안 / 미정 |
|---|---|---|
| 실행 | Pi 부팅과 BMO 실행을 분리, 바탕화면 앱 클릭 | BMO 전용 런처 하나, 중복 실행 방지, 부팅 자동 시작 OFF |
| 공존 | 추후 개인 웹서버로도 Pi 사용 | BMO 종료는 BMO 소유 프로세스만 종료. 팬·SSH·다른 서버 유지 |
| 대화 | 실제로 BMO와 대화 | 빨간 버튼으로 시작 + 말 끝 자동 감지. 무인 상시 대화는 후속 |
| 언어 | 영어 원작 BMO 우선, 한국어는 선택적 | 기본은 영어 응답. 자동 한국어 응답은 별도 설정, 기존 CLI 정책을 몰래 변경하지 않음 |
| 얼굴 | 전에 만든 디자인·부드러운 움직임 재사용 | v2 비율/색 보존 + v3 윤곽·오디오 코드 통합. 새 얼굴 재제작 금지 |
| 반복 반응 | 듣기·생각하기·반복 대사는 미리 준비 | 로컬 연출 카탈로그와 음성 캐시. 일반 대화와 구분 |
| 노래 | 보유한 BMO 노래를 로컬로 재생 | 승인한 파일만 등록, 초기 2곡 슬롯, 1곡씩 재생. 원작 음원 자동 수집은 하지 않음 |
| 게임 | 말이나 버튼으로 게임 선택, 물리 버튼 조작 | 초기 2종으로 제한. 기존 팬 게임 재사용 우선, 호환성/배포 조건 별도 확인 |
| IMU | 들거나 움직이면 놀라는 반응 | 정상 센서 확보 후 들림 유사/기울어짐/안정 이벤트만. 현재 센서는 사용 금지 |
| 팔 | 신남·모름 등을 양팔로 표현 | 보정된 이름 붙은 제스처 3개부터. 장치 안전 계층이 승인한 경우만 |
| 종료 | 버튼으로 종료할 수 있어야 함 | 초록 길게 → 홈/시스템 메뉴 → BMO 종료 확인. Pi 종료와 별도 |

## 3. 사용자가 경험할 하루

### 3.1 실행과 평상시

Pi를 켜면 바탕화면과 기존 서버가 준비된다. 이때 BMO는 아직 실행하지 않는다. 바탕화면의 BMO 아이콘을 누르면 앱은 설정·필수 자산·중복 실행 여부를 확인하고 전용 얼굴 창을 연다. 준비 완료 뒤에는 얼굴을 계속 표시하며 대기한다. 인터넷이 없어도 로컬 얼굴·메뉴·등록 노래/게임은 사용할 수 있어야 한다.

실행 실패 때는 원인과 다시 시도할 항목을 표시한다. 포트나 장치가 다른 프로그램에 점유되었다고 그 프로그램을 강제 종료하지 않는다. 카메라나 센서가 빠졌다는 이유로 기본 얼굴·메뉴까지 종료하지 않는다.

### 3.2 질문과 끼어들기

빨간 버튼을 한 번 누르면 녹음 표시가 나오고 듣기 시작한다. 말이 끝나면 녹음을 마치며, 다시 빨간 버튼을 눌러 수동으로 마칠 수도 있다. BMO는 생각하는 얼굴을 유지하다가 준비된 답을 말한다. 말이 끝나면 대기로 돌아간다.

BMO가 말하거나 생각하는 중 빨간 버튼을 누르면 현재 작업을 중단 요청한다. 첫 누름은 중단만 하고 **바로 다시 녹음하지 않는다**. 준비 표시 후 다음 누름으로 새 질문을 시작한다. 이렇게 해야 말 끊기와 의도하지 않은 녹음을 구분할 수 있다.

### 3.3 노래와 게임

"노래해 줘"는 새 노래를 LLM으로 생성하는 요청으로 처리하지 않고 등록된 곡 선택 화면을 연다. 특정 곡을 정확히 요청하면 등록 목록에서 찾아 재생한다. "게임 하고 싶어"는 게임 목록을 열고, BMO는 준비된 짧은 선택 안내를 할 수 있다. 방향 버튼으로 선택하고 세모로 시작한다.

음악·게임 중에는 마이크와 자동 대화를 끈다. 게임에서 빨간 버튼은 먼저 일시정지를 연다. 노래 중 빨간 버튼도 먼저 재생을 멈추고 준비 상태로 돌아간다. 콘텐츠와 대화를 동시에 돌리지 않는다.

### 3.4 손에 들기와 감정 표현

정상 센서가 확보된 이후, 탁자에서 들린 것과 비슷한 움직임을 감지하면 짧은 놀란 얼굴로 반응할 수 있다. 그러나 들고 걷는 동안 계속 놀라고 떠들지 않는다. 연속 움직임은 이동 중 상태로 묶고, 충분히 안정된 뒤 반응을 다시 허용한다.

들고 있거나 게임 중에는 자동 팔 동작을 억제한다. "신났어!" 같은 장면은 승인된 작은 팔 제스처와 얼굴을 조합하되, 사용자가 질문하거나 중단하면 그 연출보다 입력이 우선한다.

### 3.5 BMO만 종료

초록 원을 길게 눌러 홈으로 돌아온 뒤 시스템 메뉴에서 BMO 종료를 선택한다. 세모로 확인하면 녹음·재생·자체 작업을 정리하고 바탕화면으로 돌아간다. Pi, 팬, SSH, 개인 웹서버는 계속 작동한다. Pi 전체 종료는 관리자용으로 별도 분리하며 v1.0의 일반 버튼에는 배정하지 않는다.

## 4. 핵심 설계 선택

### 4.1 대화 시작은 버튼을 기본으로 한다

추천은 **버튼 시작 + VAD(말소리 구간 감지)로 종료**, 수동 종료도 가능하게 하는 방식이다. 배경 사람이 말한다는 이유만으로 대화를 시작하지 않는다. VAD는 말소리 여부를 감지하는 도구이지 그 사람이 BMO에게 말하는지 판단하는 호출어가 아니다.

상시 청취는 마이크 점유·오작동·원치 않는 업로드·자기 스피커 재인식까지 함께 해결해야 한다. v1.1 후보는 로컬 호출어 → 명시적 듣기 상태 → 말 끝 감지이고, 클라우드로 주변 음성을 계속 보내는 방식은 목표가 아니다. openWakeWord 공식 문서도 잡음에 대한 오인식과 환경별 임계값 조정을 다룬다. [E2]

v1.0에서 VAD가 전시 소음 조건을 통과하지 못하면 설정을 **버튼 시작/버튼 종료**로 고정한다. 실패를 숨기고 고정 시간 녹음을 VAD라고 부르지 않는다.

### 4.2 모든 반응을 GPT에 묻지 않는다

| 일 | 로컬 처리 | 클라우드 사용 |
|---|---|---|
| 깜빡임·듣는 얼굴·생각하는 얼굴 | 등록된 애니메이션 상태 | 없음 |
| 짧은 준비/오류/확인 안내 | 사전 제작 클립 | 실행 중 합성 없음 |
| 버튼으로 메뉴·노래·게임 선택 | 등록 ID 조회 | 없음 |
| 음성으로 노래·게임 선택 | STT 이후 로컬 명령 판별 | 기본 클라우드 STT 비용은 발생 가능 |
| 일반 질문 | 입력 검증·문맥·출력 제한·연출 | STT, GPT, 선택한 TTS |
| 같은 답 다시 듣기 | 현재 세션의 마지막 오디오 캐시 | 캐시가 있으면 새 합성 없음 |
| 들림 유사 반응 | 센서 이벤트와 연출 정책 | 없음 |

듣기/생각하기는 보통 **소리 없는 루프**로 둔다. "잠깐만"을 매 질문마다 말하거나 목소리로 녹음 시작을 알리면 불필요한 대기와 자기 소리 혼입이 생길 수 있으므로 기본은 짧은 화면 신호다. 과거 CLI의 `/repeat`은 재합성할 수 있지만, 새 앱에서는 캐시 재생을 목표로 한다. [S1, S3]

일반 질문이 과거 질문과 대충 비슷하다는 이유로 답을 재사용하지 않는다. 시간·날씨·개인정보·문맥 의존 답변은 고정 응답 캐시에 넣지 않는다. 저장 클립은 등록 ID로, TTS 캐시는 정확한 텍스트·언어·음성 제공자·모델/버전·속도 설정으로 구분한다.

### 4.3 얼굴·감정·입 모양은 별도 축이다

`듣는 중/생각 중/말하는 중`은 처리 단계, `기쁨/놀람/슬픔/곤란함`은 감정, `입이 열리는 정도/발음 타이밍`은 음성과의 동기화다. 셋을 하나의 PNG 번호로 섞지 않는다.

v3 소스에 이미 있는 윤곽 보간과 오디오 에너지/타임코드 코드를 사용한다. 단, 현재 v3는 오디오 중 idle 기반 얼굴에 입을 합성하므로 "웃으면서 말하기" 같은 감정 결합은 추가 연결·검증 대상이다. 음량 기반 입 움직임을 완성된 발음 립싱크라고 하지 않는다. [S3]

### 4.4 재생 담당은 하나

우선 후보는 **Pi 브라우저의 단일 재생 경로 + v3 입 동작**이다. 실제 MAX98357A 출력이 확인되어야 채택한다. Python/ALSA가 재생을 맡는 대안은 같은 오디오의 시간·에너지를 얼굴에 전달해야 하므로 비교 후 하나만 정한다. 둘을 동시에 켜지 않는다.

어느 경로든 대화 음성·노래·효과음·게임 오디오는 하나의 재생 우선순위 관리 아래 둔다. 브라우저가 Windows에서 실행되면 소리도 Windows에서 나오는 v3 동작을 Pi 출력으로 오해하지 않는다. API 키는 Python 쪽에만 두며 브라우저에 넣지 않는다. [S3, S4]

## 5. v1.0의 기능 상한

처음부터 무한한 캐릭터 기능을 만들지 않기 위해 다음을 **추천 출시 범위**로 제안한다.

| 영역 | 첫 목표량 | 포함하지 않는 것 |
|---|---|---|
| 실행/종료 | 바탕화면 런처 1개, BMO 종료 메뉴 1개 | 자동 부팅 실행, 음성으로 Pi 전원 차단 |
| 대화 | 영어 중심 1개 경로, 버튼 시작, 선택형 VAD 종료, 중단/초기화 | 상시 자유 대화, 완전한 음성 끼어들기, 다중 화자 구분 |
| 로컬 연출 | 12개 연출 슬롯; 무음 루프와 짧은 클립 | 긴 원작 대사·모든 감정 장면 수집 |
| 노래 | 초기 2곡 등록·선택·재생·중단·종료 | 노래 자동 다운로드, 생성형 노래, 가사 전체 표시 |
| 게임 | 초기 2종, 통일 메뉴·키 매핑·일시정지·종료 | 모든 애니 속 게임 재현, 모든 콘솔 에뮬레이션 |
| 센서 이벤트 | 들림 유사·기울어짐·안정 복귀 3종 | 위치 추적, 걸음/사람/낙하 안전 판정 |
| 팔 연출 | 신남·모름·인사 3종 + 중립 자세 | 자율 춤, 추종 제어, 날것의 LLM 각도 명령 |
| 설정 | 음량, 입력 방식, 목소리, 제스처, 이동 억제, 세션 초기화 | 복잡한 계정·웹 관리자·원격 장치 API |

노래 2곡·게임 2종은 **콘텐츠 수의 초기 상한/목표**이지 이미 확보한 목록이 아니다. 자산 이용 조건이나 센서 정상성이 해결되지 않으면 해당 기능을 명확히 비활성화한 `v1.0-core`로 검수하고, 그 기능을 포함한 전체 범위 완료와 구분한다.

카메라 기반 보기, 인물 인식, 장기 기억, 홈 자동화, 휴대폰 리모컨, Realtime 대화 전환, 모든 언어 지원은 v1.0 밖이다. 아이디어는 후속 목록에만 남기고 현재 작업 범위를 늘리지 않는다.

## 6. 기존 결과물 재사용 지도

| 산출물/코드 | 근거와 현재 상태 | 다음 처리 |
|---|---|---|

"노래해 줘" → 곡 목록 → 선택 → 로컬 재생과 승인된 얼굴 타임라인 → 종료 후 대기. TTS로 다시 부르는 기능이 아니며, 재생이라고 정확히 표시한다. 저작권 보호를 우회하는 다운로드나 원작 음성 복제는 이번 계획의 자동 작업에 포함하지 않는다.

## 11. 변경 관리와 Codex 경계

제품 결정은 이 문서, 세부 동작은 동작 명세, 실제 결과는 날짜가 있는 보고서에 기록한다. 같은 내용을 새 `FINAL_v4_진짜최종` 문서로 늘리지 않는다. 후속 요청에는 결정 ID·영향받는 상태/테스트를 연결한다. 하나를 추가하면 기존 범위에서 무엇을 미룰지도 결정한다.
