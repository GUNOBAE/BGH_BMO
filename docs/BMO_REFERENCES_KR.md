# BMO 레퍼런스 메모

**확인일: 2026-10-17 · 자료 조사 / 설치·실물 검증·사용자 채택 아님**

[한국어 README로 돌아가기](../README_KR.md) · [작동 구조와 개발 계획](BMO_OPERATION_PLAN_KR.md)

프로젝트 소개와 제작 기록은 README에, 제품의 상세 흐름은 [작동 구조와 개발 계획](BMO_OPERATION_PLAN_KR.md)에 정리합니다. 이 문서는 대화 구조의 근거와 사용자가 나중에 직접 볼 게임·노래 자료만 모은 별도 메모입니다. 예전 계획서의 추천값이나 자동 테스트를 사용자의 승인으로 취급하지 않습니다.

## 대화 — 두 입구를 하나의 흐름으로

**추천은 빨간 버튼과 로컬 “Hey BMO” 감지를 같은 대화 시작 이벤트로 연결하는 방식**입니다. 둘 중 하나를 택해 나머지를 버리지 않습니다. 호출어를 못 듣거나 주변이 시끄러우면 버튼을 쓰고, 탁자에 놓고 대화할 때는 불러서 시작합니다.

**설계 판단:** 발화 내용을 항상 클라우드에서 받아 호출어를 찾는 방식은 사용하지 않습니다. 로컬 호출어 감지 중에는 마이크가 열려 있음을 표시하고, 질문 시작 뒤의 오디오만 STT 단계로 넘깁니다. 기존 `wakeword.onnx`가 목표 문구를 인식하는지 확인한 다음 재사용/새 학습 필요성을 판단합니다. “헤이 비모”를 한국어 억양으로 말할 때의 인식은 별도 시험 사항입니다.

한 오디오 입력 관리자가 호출어용 신호와 질문 녹음을 나눠야 합니다. 호출어 바로 뒤의 질문 앞부분을 보존할 메모리 버퍼, 호출어 구간 제거/포함 정책, 버튼·호출어 중복 소비를 함께 검사합니다. 앱 종료 시 마이크를 닫고, 호출어 OFF 모드에서는 버튼을 누르기 전 입력을 열지 않는 것을 목표로 합니다.

### 이어 말하기와 말 끊기

“어떤 게임?”처럼 BMO가 선택을 묻는 경우에만 짧은 응답 창을 여는 안을 추천합니다. 사용자가 녹음 준비 표시를 볼 수 있어야 하며 무응답이면 닫습니다. 모든 답변 뒤 자동으로 주변 소리를 듣는 방식은 기본 OFF입니다.

발화·음악·게임 중에는 호출어를 기본 정지하고 버튼으로 중단합니다. 소리로 말 끊기까지 하려면 출력 에코·동시 녹음·취소를 별도로 검증해야 하므로, 호출어로 시작하는 기능과 완전한 양방향 대화를 한 기능처럼 표시하지 않습니다. 호출어 시작은 이번 목표에 포함합니다.

버튼 시작/호출어 시작, 붙여 말하기/잠깐 쉬고 말하기, 배경 TV/다른 사람 대화, 자기 스피커, 마이크 연결 끊김을 비교합니다. 테스트 횟수와 실제 발음·거리·잡음 조건을 남기고, 실패 시 버튼 경로를 유지합니다.

## 버튼·팔 — 새 기능보다 기존 몸의 의미를 정하기

**권장 배치는 초록=확인/A, 세모=뒤로/B, 빨강=대화/중단/게임 일시정지**입니다. 바깥쪽 초록이 누르기 편하다는 사용자 설명을 반영했습니다. 게임에서 버튼 이름을 그대로 키보드 문자로 취급하지 않고 의미별로 매핑합니다. 최종 조작감은 사용자 확인 후 확정합니다.

과거 코드 기록에는 초록 GP8=Enter, 세모 GP6=Z, 빨강 GP7=팔 토글, 오른팔 GP10·왼팔 GP11이 있습니다. 기록과 현재 파일이 같은지 확인하고, 특히 GP7의 독립 팔 토글을 그대로 둔 채 대화 버튼으로 지정하지 않습니다. 문서 수정으로 펌웨어가 변경되지는 않습니다.

팔은 정상 동작 이력이 있으므로 사용 범위에서 제외하지 않습니다. 제안하는 연출은 오른팔 한 번 들기(인사), 양팔 들기(기쁨), 작은 양팔 들기(모름)입니다. 생각/녹음 때는 쉬고, 같은 문장마다 반복하지 않습니다. 현재 팔에는 손목 회전 같은 별도 관절이 없다는 조건을 지킵니다.

새 제스처의 크기·속도·복귀는 검수 대상이며 과거 PWM 범위나 최대 각도를 곧바로 새 연출의 안전 수치로 쓰지 않습니다. **IMU 정상성을 팔 사용의 필수 선행 조건으로 만들지 않습니다.** IMU는 보류하고, 안정된 탁상 상태에서 팔을 쓰며 이동 시 운영자가 끄는 수단을 둡니다. 센서로 자동 이동 억제를 한다고 주장하지 않습니다.

## 게임 — 사용자가 먼저 해볼 후보

게임은 급하지 않은 별도 선택 과제입니다. 브라우저에서 재미·조작을 먼저 보고, 그다음 Pi 실행 형식과 종료 방법을 조사합니다. 이번에는 다운로드·설치·실행을 하지 않았습니다.

### 먼저 볼 것: Virtual BMO — Gumpy Function

**[제작자 페이지에서 플레이](https://gumpyfunction.itch.io/virtual-bmo)**

BMO 얼굴/바탕화면을 탐색하고 그 안의 *Guardians of Sunshine* 게임을 실행할 수 있는 팬 작품입니다. 제작자 페이지에는 HTML5 체험과 `BMOv3.1.gb`, `.pocket`, GB Studio 소스가 있습니다. 기본 방향키와 A/B·Start 구조는 이 로봇의 버튼 구성과 비교하기 좋습니다. 원작 얼굴 UI는 참고용이고 우리가 좋아한 v3 얼굴을 이것으로 바꾸는 계획은 아닙니다.

PC 체험에서는 방향키, Z(A), X(B), Enter(Start)를 사용합니다. 화면별 조작은 제작자 표를 확인하세요. 향후 BMO에서는 초록=A, 세모=B, 빨강=일시정지로 매핑하는 안을 검토합니다. 저장/탈출 지원과 Pi 성능은 아직 모릅니다.

[제작자의 소스 공개 안내](https://gumpyfunction.itch.io/virtual-bmo/devlog/950618/virtual-bmo-source-code-now-available)에 따르면 **공개 소스에서 기존 음악·효과음을 제거**했습니다. 소스 수정본을 만들면 음향 자산은 따로 준비해야 합니다. 다운로드 게임과 수정 소스의 구성·사용 조건을 구분합니다.

### 비교할 것: Guardians of Sunshine — Chewbacan

**[제작자 페이지에서 플레이](https://chewbacan.itch.io/guardians-of-sunshine)**

별도의 Godot 기반 HTML5/Windows 팬 게임입니다. 제작자가 안내하는 이동은 WASD/방향키, 기본 행동은 J/Z와 K/X이며, 내려받는 파일은 Windows 32/64비트판입니다. **Windows ZIP을 Pi ARM64용이라고 취급하지 않습니다.** 로컬 웹 빌드의 제공·이용 조건과 Pi 호환성을 추가 확인해야 합니다.

선정 기준은 원작 느낌, 재미, 여섯 조작 버튼으로 충분한지, 인터넷 없이 실행되는지, 언제든 BMO 홈으로 돌아오는지입니다. 어떤 게임도 사용자 채택이나 실물 동작 완료로 표시하지 않습니다. 게임 수를 채우려고 새 대형 게임을 만들지 않습니다.

## 노래 — 곡수 제한 없이 원작 목록부터

로컬 파일을 준비하면 요청할 때마다 다운로드하거나 합성할 필요가 없습니다. 곡 선택과 재생 시스템은 곡 수와 분리해, 이후 확인된 곡을 코드 재작성 없이 등록할 수 있게 설계합니다. 반주에 입이 과하게 반응할 수 있어 곡별 보컬 타임라인을 우선 검토하고, 없는 경우 에너지 기반의 한계를 표시합니다.

**이번 완료 범위는 자료와 계획 정리입니다. 음원 추출·다운로드·전체 곡 수 확정·로컬 재생 검수는 하지 않았습니다.**

## 근거를 사용하는 방식

외부 제작자/공식 문서에서 확인한 기능은 레퍼런스의 기능입니다. 이 로봇에 이미 구현됐다는 뜻이 아닙니다. 현행 코드의 근거는 [야간 작업 보고서](https://github.com/GUNOBAE/BGH_BMO/blob/a2f895ea9f078c655f0db1a17d704008bbde7bb5/docs/reports/NIGHTLY_STATUS.md), 하드웨어·사용자 선호는 이전 프로젝트 기록과 2026-10-17 최신 요청입니다. 연구·추천과 사용자 최종 승인을 나눕니다.

이 메모는 조사 후보를, [작동 구조와 개발 계획](BMO_OPERATION_PLAN_KR.md)은 제품 흐름을, README는 프로젝트 소개와 제작 기록을 관리합니다. 새로운 채팅에서도 게임 부분만 읽어 이어갈 수 있지만, 다른 채팅을 자동 생성하거나 거기서 작업을 시작한 것은 아닙니다.
