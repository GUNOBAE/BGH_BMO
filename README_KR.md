## 우리가 만들 BMO

Raspberry Pi는 다른 개인 웹서버와 함께 사용할 수 있게 상시 켜 둡니다. **BMO 앱은 부팅 때 자동으로 시작하지 않고, 바탕화면 아이콘으로 따로 실행하는 방향**입니다. BMO를 종료하면 바탕화면으로 돌아가고 팬·SSH·다른 서버는 유지합니다.

목표 동작은 대기 얼굴 → 질문 듣기 → 대답 준비 → 말하기 → 다시 대기입니다. 듣기·생각하기·짧은 인사 같은 반응은 로컬 연출을 재사용하고, 새로운 질문의 내용은 클라우드 GPT가 담당합니다. 노래와 게임은 등록된 로컬 콘텐츠를 메뉴에서 선택합니다. 정상 센서와 검증된 팔 동작이 확보되면 들림·기울임 반응과 감정 제스처를 추가합니다.

**기본안:** 빨간 버튼으로 질문 시작, 파란 세모로 확인, 초록 원으로 뒤로가기, 십자 버튼으로 이동. 게임에서는 세모·초록 원을 A/B로 사용하고 빨간 버튼은 일시정지에 예약합니다. 기존 GP7 빨간 버튼의 팔 토글은 별도 감독 검증 전까지 바꾸거나 눌러 시험하지 않습니다.

## 현재와 목표를 구분합니다

| 항목 | 현재 확인된 상태 | 목표 |
|---|---|---|
| 대화 기반 | 클라우드 STT/GPT/TTS 코드와 오류 처리 존재 | 한 앱에서 실제 대화와 얼굴 연결 |
| 화면 | PNG 렌더러·유한 모의 대화 데모 존재 | 선호한 v2 디자인과 v3 연속 윤곽 구현 재사용 |
| 안정성 검사 | 야간 보고서에 회귀 169개 + 화면 검사 8개 통과 기록 | 실물 대화·미디어·장시간 동작 검증 추가 |
| v3 원본 | 별도 HTML·Lab 패키지와 연구 문서 존재 | 버전·해시를 확인해 필요한 코드만 편입 |
| 입력 | 기존 RP2040 HID/팔 펌웨어와 새 제품 배치가 다름 | 물리 입력을 앱의 의미별 동작으로 매핑 |
| 팔·IMU | 호스트 팔 제어 차단, MPU6050 이상 진단 기록 | 정상성·보정·안전 범위를 검증한 경우에만 활성화 |
| 노래·게임·바탕화면 런처 | 최종 통합은 미구현 | 제품 계획의 한정된 범위로 개발 |

169+8은 저장된 보고서의 결과이며 이번 문서 작업에서 다시 실행한 검사가 아닙니다. 과거 개별 하드웨어·음성 대화 실험과 새 통합 앱의 검증 여부도 구분합니다.

## 하드웨어 기준

| 구성 | 기준 |
|---|---|
| 메인 | Raspberry Pi 5 **8GB**, Debian 13 / ARM64 |
| 화면 | 7인치 DSI, 조사 기록의 실제 출력 800×480 |

| 반응 장치 | 팔 서보 2개, MPU6050, Camera Module 3 Wide |
| 냉각 | 기존 독립 팬 제어 유지 |

## 개발 범위와 운영 원칙

제품은 **8개 작업 묶음**으로 관리합니다: 원본 인수인계, 실행/화면, 대화/입력, 로컬 연출, 노래, 게임, 센서/팔, 통합 안정화. 세부 목표·보류 기능·합격 조건은 제품 계획서에 있습니다. 모든 기능을 한 번에 켜거나 매번 처음부터 다시 만드는 방식은 사용하지 않습니다.

코드 작성 → 모의 검사 → 실물 확인 → 사용자 체감 승인 네 단계를 구분합니다. 실제 모델·녹음·노래·게임 파일·개인 설정은 검토 없이 공개하지 않습니다. GitHub의 문서 변경이 Pi 파일·실행 상태에 자동 적용되지는 않습니다.
